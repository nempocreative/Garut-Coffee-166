name: Direct Web UI edits
description: Project-specific preference to apply requested Web visual changes directly in the existing app.

For Garut Beans Web visual refinements, edit the existing Web artifact directly. Do not create new Canvas design or mockup frames unless the user explicitly requests a preview or alternatives.

**Why:** The user explicitly repeated that visual changes should be applied directly to Web and not made as a new design.

**How to apply:** For straightforward visual requests on the selected Web artifact, update its existing source and verify the actual Web preview while keeping the Canvas free of new mockups.

For the Web page background, use a subtle rough, asphalt-like aggregate texture rather than paper/topographic contour lines or a plain white surface. Keep foreground cards and text readable against it.

**Why:** The user clarified that “textured” means a coarse asphalt-like surface, not the previous paper contour pattern.

**How to apply:** When changing the Web background, preserve clear contrast for the foreground and avoid illustrative line patterns.

For account-page refinements, use the existing warm coffee, cream, and terracotta palette; avoid dominant green surfaces and oversized decorative panels.

**Why:** The user explicitly asked that the account page match the Web theme without green or large shapes.

**How to apply:** Keep the textured page background visible and limit solid surfaces to the functional account card.

For the Garut Beans Web artifact, keep the desktop experience full-width; do not force desktop visitors into the 430px phone frame. Keep phone-only homepage refinements scoped to narrow screens.

**Why:** The user clarified that the phone-width desktop view looked wrong and asked to restore the real desktop layout while limiting the requested refinements to mobile.

**How to apply:** Keep the standalone desktop route and its wide responsive layout. Scope mobile-only overrides below 420px and verify a 1440px desktop plus 390px and 320px phone views.

For the Garut Beans Web informational footer, keep only the brand, short tagline, and copyright/location. Keep the primary bottom navigation separate and show it on every page, including desktop.

**Why:** The user explicitly asked for a simple informational footer without navigation links, and separately asked for the bottom navigation to appear on every page.

**How to apply:** Render one shared bottom navigation across all routes; reuse the compact informational footer on pages that include it.

For homepage sections, vary the composition instead of putting every section in a large card.

**Why:** The user said repetitive, oversized cards make the homepage feel monotonous.

**How to apply:** Prefer editorial rows or compact inline layouts where they fit, and use large cards only when containment adds value.

For customer-facing coffee taste choices, lead with everyday Indonesian phrasing and put specialty-coffee terms in parentheses.

**Why:** The user noted that many visitors may not understand coffee tasting jargon and chose everyday wording with the coffee vocabulary retained in parentheses.

**How to apply:** Use this wording for taste-preference controls in the Garut Beans Web experience while keeping the underlying coffee-profile matching intact.

For Garut Beans Web menu headers, show the page title without small subtitle text immediately below it.

**Why:** The user explicitly requested no small text beneath titles and corrected that subtitles remained in other menus.

**How to apply:** Omit subtitle text below page titles across menu headers while preserving explanatory copy in the page body.

For Garut Beans product imagery, including coffee by-products, use Cikuray Series as the strict brand and composition reference. Keep its brand mark, kraft-and-cream packaging, blue batik details, Garut landscape illustration, framing, lighting, and surrounding scene consistent; adapt the package shape only when the product format requires it.

**Why:** The user corrected an earlier Papandayan image as too different and reiterated that product imagery, including coffee soap, must follow the existing Cikuray reference rather than drift into a generic style.

**How to apply:** Start product image edits from the Cikuray Series image. Preserve its visual identity and specify only the product-specific label and any format changes needed for the item.

For Garut Beans Web, use the Coffee Scrub Soap photo as the shared visual reference for Essential Oil, Pewangi Sepatu, Minyak Aroma, Konsentrat Kopi, and Cookies Ampas Kopi while preserving each product's format.

**Why:** The user wants these products to look like one family alongside the Sabun Scrub and Totebag references; isolated restyling produced too much scene variation.

**How to apply:** For this product group, start from the Sabun Scrub photo and replace only the central product, preserving its scene and composition. Keep the cream/kraft label, Garut Beans mark, blue batik accents, Garut illustration, tabletop, and warm lighting; retain each product's own spray bottle, dropper bottle, concentrate bottle, or cookie pouch. Use the Cikuray Series reference for products without a more specific style reference.

For Garut Beans Web, keep photo and icon files lightweight, preserve their intended on-screen proportions, and show a local fallback rather than a broken or empty image when a file fails to load.

**Why:** The user explicitly asked that website photos and icons not be oversized or disrupt the layout, and that photos not suddenly disappear.

**How to apply:** Prefer optimized image formats for Web assets, verify the mounted asset paths and responsive crops, and keep a local fallback for failed image loads.

For the Garut Beans gift-box visuals, arrange the original catalog products inside the box and preserve each package design exactly; do not generate replacement packaging.

**Why:** The user clarified that the products should be arranged inside the box and that their packaging must match the existing catalog designs.

**How to apply:** Use the original product-photo pixels as cutouts over an empty gift-box backdrop, with the greeting card visible in the composition.

For a closed gift-box concept, keep the Garut Beans box form and batik trim, and make the lid artwork echo the coffee bags with the Garut Beans name and the Ayo Ngopi poster's white ram mascot in its blue branded shirt holding a coffee cup; avoid a rigid badge-like layout.

**Why:** The user supplied the Ayo Ngopi poster as the exact mascot reference after rejecting a generic sheep design.

**How to apply:** Use the real box photo as the structural reference and the poster as the mascot reference; blend the mascot and brand into the lid and front artwork without replacing the box with unrelated packaging.

For the Garut Beans Web homepage, the location selector is for partner outlets where customers can try and order Garut Beans, not for customers' personal delivery addresses. Add personal delivery addresses during checkout.

**Why:** The user clarified that homepage locations should represent partner outlets, while delivery addresses belong in checkout.

**How to apply:** Show partner locations on the homepage in every service mode; use saved delivery addresses only in the cart/checkout flow.

Keep the accumulated points balance on the Garut Beans Web homepage, but put point explanations, reward redemption, and active-voucher details on a dedicated points page instead of the member/outlet panel.

**Why:** The user asked to remove “Tukar hadiah” from the homepage panel, then asked the balance box to open a dedicated points page.

**How to apply:** Keep the homepage panel balance-only and link it to the points page; explain earning and redemption there, then let customers apply active vouchers in the cart/checkout flow. The point value and voucher cost are 1 PT = Rp1.
