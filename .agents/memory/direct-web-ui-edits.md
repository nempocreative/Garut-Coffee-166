---
name: Direct Web UI edits
description: Project-specific preference to apply requested Web visual changes directly in the existing app.
---

For Garut Beans Web visual refinements, edit the existing Web artifact directly. Do not create new Canvas design or mockup frames unless the user explicitly requests a preview or alternatives.

**Why:** The user explicitly repeated that visual changes should be applied directly to Web and not made as a new design.

**How to apply:** For straightforward visual requests on the selected Web artifact, update its existing source and verify the actual Web preview while keeping the Canvas free of new mockups.

For the Web page background, use a subtle rough, asphalt-like aggregate texture rather than paper/topographic contour lines or a plain white surface. Keep foreground cards and text readable against it.

**Why:** The user clarified that “textured” means a coarse asphalt-like surface, not the previous paper contour pattern.

**How to apply:** When changing the Web background, preserve clear contrast for the foreground and avoid illustrative line patterns.

For account-page refinements, use the existing warm coffee, cream, and terracotta palette; avoid dominant green surfaces and oversized decorative panels.

**Why:** The user explicitly asked that the account page match the Web theme without green or large shapes.

**How to apply:** Keep the textured page background visible and limit solid surfaces to the functional account card.

For Web sign-in, use a genuine desktop layout above the desktop breakpoint instead of constraining the page to the mobile app's 430px width. Keep it fluid and stack the content only on narrow screens.

**Why:** The user corrected a 430px-wide sign-in layout because it made the Web page look like a mobile screen.

**How to apply:** Keep the desktop sign-in content at a controlled web width with a desktop composition; verify both desktop and phone layouts.

For the Garut Beans Web footer, keep only the brand, short tagline, and copyright/location; do not add a navigation menu. Show the same footer across all pages.

**Why:** The user explicitly asked for a simple footer without a menu, then asked to show it on every page.

**How to apply:** Reuse the same compact footer on the home page, routed content pages, and sign-in page.

For homepage sections, vary the composition instead of putting every section in a large card.

**Why:** The user said repetitive, oversized cards make the homepage feel monotonous.

**How to apply:** Prefer editorial rows or compact inline layouts where they fit, and use large cards only when containment adds value.
